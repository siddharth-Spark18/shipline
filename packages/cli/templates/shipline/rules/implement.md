# Implement rules

<!-- Repo-specific instructions Claude must follow in the "implement" stage. Filled in by /shipline-setup; edit freely. -->

- Follow the plan and the repo's existing patterns: naming, file layout, error handling, state management and style.
- Keep the diff to the files the plan lists. If another file genuinely has to change, change it and say why.
- Note every deviation from the plan, and anything left out, in `implementation.md`.
- Don't add dependencies, refactors or features the plan didn't ask for.
- Read the surrounding code before editing it, and match its conventions even when you would do it differently.
- Don't commit or open a pull request in this stage; that comes after verify.
- Write code that handles the plan's edge cases, not just the main path.
