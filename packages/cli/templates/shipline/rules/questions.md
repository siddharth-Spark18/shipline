# Open questions rules

<!-- Repo-specific instructions Claude must follow in the "questions" stage. Filled in by /shipline-setup; edit freely. -->

- Ask only questions whose answers change the implementation. If the answer would not change what you build, decide and move on.
- Check the ticket, the feasibility notes and the code first. Don't ask what they already answer.
- Group related questions and ask them together with the AskUserQuestion tool, with concrete options where you can. Offer your recommended choice first.
- Record each question and the developer's answer in `questions.md`, so later stages can read them.
- If there is nothing to ask, write `questions.md` saying so and why.
- Don't start implementing while a question that blocks the work is unanswered.
