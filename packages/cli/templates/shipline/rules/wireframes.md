# Wireframes rules

<!-- Repo-specific instructions Claude must follow in the "wireframes" stage. Filled in by /shipline-setup; edit freely. -->

- Follow the existing UI: reuse its components, spacing, colors and wording instead of inventing a new look.
- Show every state: empty, loading, error and filled. Give each state its own variant.
- Show small and large screens when the layout changes between them.
- Label each variant and note what the user can do in it, so the plan's behavior can be checked against it.
- Keep wireframes simple and clearly marked as proposals. Save them as the stage's artifact.
- Where the UI has an existing page for this, base the wireframe on a view of the current page.
